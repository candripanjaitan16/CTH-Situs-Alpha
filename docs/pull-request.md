# Install from GitHub with isolated per-user data and a production launcher

The previous launcher required a live Vite development server and stored SQLite, workspace and Google authentication beside the backend source. Install/update now builds a separate per-user release, installs `chanthecno-hub` in `~/.local/bin`, and serves the production frontend and API through one loopback server. No sudo or npm package publication is used. Reinstallation and uninstall preserve user data/configuration by default; PATH, GitHub update/uninstall, and individual-account OAuth instructions are documented.

Shared paths and atomic storage isolate data from code and credentials. Offline reset/restore requires explicit confirmation, refuses active/uncertain work, verifies a SQLite/WAL-aware backup first, and leaves OAuth configuration and Google resources untouched. Colab/Drive connection handling and GPU checks reuse the existing guarded connection lifecycle. Model history remains selectable after a newer failed job or failed backup, existing runtime artifacts avoid a repeated restore, stale progress requires a fresh worker heartbeat, and retrying backup never starts training.

Model Testing uses the chosen model name, a collapsible mobile library and a visible composer. Retrieval uses overlapping passages; the same adapter/model can answer from general knowledge when project evidence is missing, with cautious attribution. This is not evidence of improved real-model quality. Checkpoint resume now requires optimizer/scheduler/RNG state with matching checksums. Legacy checkpoints without these integrity markers are rejected for exact resume.

Validation: 32 offline backend tests, real temporary-directory install/reinstall/start/shutdown/uninstall smoke, production build, lint (18 warnings, exit 0), and Chromium desktop/mobile tests with mocked APIs. Screenshot fixtures and detailed evidence are in `docs/validation.md`. Google OAuth/Drive/Colab/T4, full training/resume, Linux Mint memory use, and adapter quality were not tested against real services. CI configuration is included but its remote run is unverified. No credentials were read or distributed; no Google resources were changed. See README for retained limitations, reset scope and recovery commands.
